# repl-plugin-player

オーディオプラグインを[REPL](https://en.wikipedia.org/wiki/Read%E2%80%93eval%E2%80%93print_loop)ライクなUIで演奏。[UAPMD](https://github.com/atsushieno/uapmd)を利用しています。Rustで書かれています。

機能にクセがあります。ほぼ自分専用です。明日には仕様変更して今までのファイルが読めなくなる可能性があります

## ダウンロード

[Windows版をダウンロード](https://github.com/cat2151/repl-plugin-player/releases/download/v0.1.0/repl-plugin-player-0.1.0-windows-x64.zip)

実験用プロジェクトなのでときどき404です

## これまでの課題と、このアプリが解決すること

### オーディオプラグインをscriptで鳴らす遊び

- DAWはオーディオプラグインで高品質な作編曲ができて素晴らしいですね！
  - ですがオーディオプラグインを演奏するには「DAWの使い方」を学ぶ必要があります。
    - 特に主流のDAWはそれが顕著で、慣れるまではハードルが高い。
- ライブコーディングはプログラムで音楽ができて素晴らしいですね！
  - ブラウザのplaygroundもあり、入門しやすいです。
  - とはいえ専用の文法を学ぶ必要があり、慣れるまでにちょっとハードルはあります。
  - また、ネイティブの大規模VST3/CLAPオーディオプラグインにデフォルトで対応してバイナリ一つで起動直後からそれらを鳴らせるものは見つかりませんでした。
- さて、ファミリーベーシックやMSXの時代は、`PLAY "CDE"` のような記述でドレミを演奏できました。
  - 直感的ですね！
  - そして `CDE` の部分はプログラムでその場で生成することもできました。
- アプリを起動したら `play("cde")` を入力してVST3/CLAPオーディオプラグインを鳴らせる、演奏内容そのものをプログラミングして即座に（時間のかかるビルドなしに）演奏できる、そんな遊びをしてみたいと思いました。
- 現代は、ほしいUXがあれば、バイブコーディングで実現できます。
- そうすることにしました。

## 補足
- イメージの補足
  - リッチな音色を、プログラマブルに遊ぶ
    - ブラウザ上の各種音色よりも、もっとリッチに（ネイティブのVST3/CLAPの音色をフルに鳴らせるので）
    - MMLよりも、もっとプログラマブルに
    - 音楽プログラミング言語よりも、もっとscriptライクな文法とコーディング内容で
    - VSCodeを使う音楽プログラミング言語よりも、もっとシンプルな環境構築で（GitHubからexeをダウンロードして実行するだけ）
    - ネイティブアプリを都度ビルドするよりも、もっと素早くイテレーションをまわせるかもしれない（用途によっては）
  - 使い分け
    - ブラウザなら、機種を選ばず鳴る
    - MMLなら、もっと小さい記述量で、素早く音楽（譜面）を構築して演奏して楽しめる
    - 音楽プログラミング言語なら、もっと波形単位で表現ができるし、より素早く多様な記述ができる
    - VSCodeを使う音楽プログラミング言語なら、より効率的なキータイピングで、より素早く結果が得られる
    - ネイティブアプリなら、より大編成でリッチな（マシン処理負荷の高い）音を鳴らすことができる
- 互換性がない
  - scriptingの仕組み上、この上に音楽プログラミング言語のlayerを乗せる等、いろいろなことが可能でしょう
    - ただし、このprojectは頻繁に破壊的変更をします
      - よって現実的には「そうやって作り込んでも、すぐに演奏不可能になる」可能性が高いです
        - データ移行のコストは大きいでしょう（AIを利用してコスト軽減できる可能性があるとはいえ）
          - ですので、そういった作り込みをせず、小規模に遊びましょう
