# ADR 0013: 最後の cell を実行したら空の cell を足して移り、easy の起動は見本の cell を置く

- 状態: 採用
- 決定者: user（空欄にプレースホルダー `play("cde")` を出すと cell 方式に気づかず1つの cell に複数書いてしまう、という問題提起・実行したら次の空の cell へ進む方向・それを easy かどうかに関わらず常に効かせること・起動時の `easy-init` の cell を折りたたまないこと）。起動時のエディタの並び（`easy-init`、`easy-play`、空の cell）と、起動時に実行するのを先頭の cell だけにすることは AI の設計
- 関連: [0012](0012-easy-layer-with-global-state.md)（easy の層）

## 決定

- Ctrl+Enter（または cell 実行のボタン）で実行した cell が文書の最後の cell なら、末尾に `// %%` を足し、その下の空の行へカーソルを移す。最後でない cell と、選択範囲・行の実行では足さない。足す操作は1回の undo で戻る。
- easy style で起動したエディタは `easy-init` の cell、`easy-play` の cell、空の cell の順に並べ、カーソルを空の cell に置く。起動時に実行するのは先頭の `easy-init` の cell だけにする。

## 理由

- easy の層は1行の関数呼び出しで1つの機能を使う。MSX-BASIC の感覚で `play` を1つの cell に続けて書くと、Ctrl+Enter で全部がまとめて実行される。user が実機で確かめたところ、1つ目の `play` の頭だけが鳴って、すぐ2つ目に変わった。実行のたびに次の cell へ進めば、説明の文字を画面に出さなくても「1回の実行 = 1つの cell」が手に馴染む。
- 起動時に見本の cell を本物のテキストで置けば、cell の区切り線と1行の呼び出しの形が、書き始めても消えずに残る。
- easy かどうかで動きを分けると、実行の規則が2通りになる。user の判断で常に効かせる。
- `easy-play` を起動時に実行すると、起動しただけで音が鳴る。起動時に実行するのは定義の cell だけにする。

## 却下した案

- **空欄にプレースホルダー `play("cde")` を出す。** 打ち始めた瞬間に消えるので、cell の区切りを一度も見ないまま書き進めてしまう。
- **`// %%` を含む複数行のプレースホルダーを出す。** 同じ理由で、見本が要るときには消えている。
- **easy のときだけ Enter で1行ずつ実行する。** cell 方式とは別の実行モデルになり、mode が1つ増える。
- **`easy-init` を隠して起動時に実行するだけにする。** 既定の plugin・patch・tempo を cell で直せなくなる（ADR 0012 の理由）。

## 結果

- easy の起動後の Ctrl+Enter は、cell が1つずつ下へ増えていく使い方になる。
- 非 easy でも、最後の cell を実行するたびに空の cell が足される。
