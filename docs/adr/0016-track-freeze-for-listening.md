# ADR 0016: 音楽を聴くUXを優先してtrackのauto freezeを試す

- 状態: 採用
- 決定者: user（音の途切れをなくして音楽を聴く人のUXの改善を優先し、UAPMDのauto freezeをUX検証する。期限超過した曲だけのfreezeを希望し、複雑になるなら手動on/offのsnippetsから小さく始める）。導入範囲はAIの判断
- 関連: [ADR 0015](0015-exported-sfz-and-routed-gains.md)、[音声デバイスのバッファサイズ補修](../../patches/uapmd/device-buffer-size/README.md)

## 決定と理由

音符の時刻を保持する補修と、要求した音声デバイスのバッファサイズを反映する補修を行っても、重い音源での音の途切れが残った。
実利用の4trackのprojectでは、1024 framesを反映してもsforzandoとTONE3000を使うtrackが48 kHzで約17.1 msのworker処理期限を超える場合があった。
2048 framesでも反復試聴の一部で期限超過したため、バッファの拡大だけで解消するとは判断できない。

音の途切れをなくして音楽を聴く人のUXの改善を優先する。そのためUAPMDのtrack auto freezeを導入してUX検証する。
停止中にtrackを音声へ生成する待ち時間とキャッシュのコストを引き受け、試聴中のplugin処理を減らす選択である。
軽量の曲まで一律にfreezeせず、期限超過した曲だけを対象にすることを目指す。

参照したUAPMD `4ec5c3b1c30130fdd3b7d4b375082273247e561f`にはtrackごとのfreeze policyと状態取得のJS APIがある。
onでは停止して余韻が収まった後に非同期生成し、編集でキャッシュが無効になると再生成する。再生中にonにした場合の生成は停止後に延期される。
ただし処理期限超過に応じた曲の選別はこのpolicyに含まれず、独自の判定と停止・再生の制御が必要になる。
userが小さな導入を選んだため、当初は既存APIを直接呼ぶtrack単位のon/offと状態確認のsnippetsにとどめ、自動停止も追加しなかった。
config、処理期限超過による独自の選別、全曲の一律freeze、新しいrepl APIは追加しない。重いtrackの選択は利用者が行い、軽い曲の再生経路を変えない。

userから、譜面上の演奏が終わってもStopを押すまでfreezeされないと報告された。
曲末を過ぎてもtransportが再生中のまま残るため、余韻が収まるだけでは停止待ちを抜けない。
freeze待ちがある場合に限り、loopが無効で曲全体の末尾を過ぎたらplayheadを保持して自動停止し、通常の余韻処理を経て生成へ進む。
loopやlive device inputがある演奏は末尾だけで終了を決められないため対象にせず、freeze待ちのない演奏も変えない。

また、freezeするとkeyboardとscopeが空になると報告された。plugin処理箇所での観測が、pluginを省略するfreeze再生でも続くという前提が不足していた。
表示のためにpluginを再処理するとfreezeの目的を失うため、keyboardは予定されたMIDI、scopeは再生中のキャッシュ音声から観測する。
キャッシュはtrack全体の音声なので、freeze中のscopeは選択plugin単体ではなくeffectsを含むtrack出力を示す制限を引き受ける。

生成失敗、初回の待ち時間、編集後の再生成、off後の生演奏への復帰もUXの評価対象にする。
実利用projectの凍結後の出力と処理期限超過を確認し、数値上の成功だけで聴感上の途切れの解消を断定しない。
同じ4trackのprojectを全track凍結した場合、生成待ちは約2.3〜2.5秒で、新規プロセスによるloopなしの15秒の再生を3回行って処理期限超過はすべて0回、有限で非ゼロの音声出力を得た。
この結果は手動freezeを試す根拠とし、重いtrackだけの凍結や聴感での評価まで保証したものとは扱わない。

userからloopの折り返し後に無音になる報告があり、1秒のloopで再現した。通常のclipに適用されるloop位置への折り返しが、freeze音声の読み出しにも適用されるという前提が崩れていた。
freeze音声は増え続けるcallbackの再生位置でキャッシュを読み、最初の演奏と余韻の後は末尾を越えて無音を返していた。
キャッシュの生成内容や保存形式は変えず、再生時の読み出し位置と先読み位置をloop範囲へ戻し、block途中の境界では読み出しを分割する局所補修を採る。
loopのたびに再生成する案は、安定した試聴のために待ち時間を先払いするfreezeの目的に反するため採らない。オフライン生成は引き続きloopを適用しない。
保存はUAPMD既存のpolicyとキャッシュの形式を使い、projectや設定の形式を変更しない。既存projectの一度限りの移行は不要である。
