# ADR 0034: マイク録音の UX 検証では WAV を外部参照する

- 状態: 採用
- 決定者: user（同梱より UX 検証を優先）
- 関連: [0030](0030-audio-device-opened-playback-only.md)（UAPMD の再生デバイス）

## 背景と決定

snippet からマイクで録音し、タイムライン上のオーディオとして再生できるようにする。UAPMD は入力デバイスとオーディオクリップを扱えるが、調査した版にはマイク入力を録ってクリップにする機能がなかった。また、UAPMD の入出力を同時に開く構成では、入力待ちによって再生開始直後に音が途切れた経緯がある。

UAPMD の再生専用構成を保ち、マイク入力は Rust 側で扱う。録音を停止したら、録音開始時の再生ヘッド位置に UAPMD 標準のオーディオクリップを置く。これにより、開始と停止の操作、配置、再生までの使い勝手を先に確かめられる。

ユーザーが停止前からタイムライン上で録音を確認できることを求めたため、録音中は同じ位置に表示用のレーンを出す。停止時にクリップを確定する方針を維持し、保存や再生が参照する WAV は確定後のものとする。録音中の解析方式は [0035](0035-wav-pitch-overlay-uses-uapmd.md) に記す。

当初は録音中だけマイクを開き、録音データのピークをモニターに表示していた。録音前に入力レベルを確認したいという要望を受け、モニターを開いている間もマイクを開く。モニターの開閉から録音を独立させるため、録音とモニターはそれぞれ共有モードで入力を開き、録音中の表示には WAV に書き込む入力のピークを使う。

初版では WAV をアプリのローカルデータに保持し、`.uapmdz` への同梱は行わない。保存したプロジェクトの再生には元の WAV が必要になる。録音の操作とタイムライン上の扱いが固まった後で、プロジェクトを持ち運ぶための同梱を検討する。
