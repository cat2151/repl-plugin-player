# ADR 0026: evolve は、期限超過が1回あれば次の音色へ進む

- 状態: 採用
- 決定者: user（重い音色で無音が続くなら、すぐ skip する。「期限超過したら次の音にいっていい」として、窓と割合で判定する案を採らなかった）。判定を `evolve-dll` の `Playback::begin` に置くこと、遅れた block も期限超過に数えること、どの slot を外すか・今の音色は外さず早めに fade することは AI の設計
- 関連: [ADR 0017](0017-evolving-loop-prototypes.md)、[ADR 0019](0019-evolve2-async-pool.md)、[ADR 0025](0025-evolve-loudness-trim-and-limiter.md)、[ADR 0027](0027-evolve-groups-injected-from-js.md)（group が複数のとき、blame は全 group から1件だけ選ぶ）

## 決定と理由

user から報告があった。Six Sines の音色が1分ほど 1024 frames に収まらず、次の音色へ進まないまま無音が続いた。UAPMD は期限に間に合わない block を丸ごと捨て、その block の after callback（`mix`・`finish`）を呼ばない。[ADR 0025](0025-evolve-loudness-trim-and-limiter.md) の測定は `mix` でしか進まない。このため、重い音色を gain 0 で鳴らしている間は、もう一方の slot の測定も終わらず、どちらも聴こえる状態にならない。`try-evolving-sequencer` の流れで「Hope Evolution」を選ばせると、2 slot とも60秒間測定が終わらず、無音のままだった。

- **期限超過は、捨てられた block（`begin` の後に `finish` が来ない）と、遅れた block（`begin` から最後の `finish` までが1 block の長さを超える）の両方を数える。** Hope Evolution は鳴り始めて数秒後から重くなる。そうなると、ほぼ全部の callback が捨てられずに遅れて完了し、callback の回数が毎秒47回から約35回に落ちた。捨てられた block だけを数えると、この状態を見逃す。
- **期限超過の1回目で、測定中の slot（2つあれば後に engage した方）を外す。測定中が無ければ、fade で入ってくる slot を外す。** 外した slot は通常の retire と同じ経路で loader に返り、JS が次のランダム音色を要求する。
- **今の音色だけが鳴っているときの期限超過では、外さずに印を付ける。印の付いた音色は、次の音色が測り終わったら hold を待たずに fade で抜ける。印がある間は、期限超過があっても何も外さない。** 軽い音色どうしでも期限超過が2 block 続くことがあり、今の音色を外すと、次の音色が測り終わるまで無音になった（候補を絞った試験で約6秒）。今の音色が重いと分かった後で測定中の側を責めると、次の音色がいつまでも測り終わらない。

## 却下した案

- **1秒の窓で、4分の1以上が期限超過なら外す。** 軽い音色を偶然の1回で外さずに済むが、user は1回で次の音色へ進むことを選んだ。
- **印の付いた音色を、2回目の期限超過で外す。** 上の無音が出た。

## 結果と制限

Hope Evolution と Surge XT の3音色に候補を絞った90秒では、Hope Evolution は毎回測定中に外れ、残った側は鳴り続けた。

偶然の1回の期限超過でも、測定中の軽い音色が外れる。今の音色が重くなった場合は、次の音色が測り終わるまで途切れながら鳴る。最初の slot だけが測定中に期限超過すると、それが外れ、次の音色が鳴るまで無音になる。外した音色は覚えないので、同じ音色が後でまた選ばれることがある。
