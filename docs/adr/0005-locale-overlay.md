# ADR 0005: 配布版の UI 文言は、埋め込みの既定に user が変えたキーだけを重ねる

- 状態: 採用
- 決定者: user（user が文言を変えられる用途を残すこと・user が触っていないキーは常に新しい exe の文言にすること・既定は読み取り専用で user のファイルには変えたキーだけを書く重ね合わせにすること・base を控える方式を採らないこと）。`<lang>.default.toml` を参照用に書き直すこと・未知キーと placeholder 不一致を黙って捨てること・壊れた toml でエラーにすること・開発時の厳密な読込を変えないことは AI の提案
- 関連: [0003](0003-build-boundary.md)（repo の中の exe は locale を source tree から読む）

## 決定

- repo の外の exe は、文言を埋め込みの `locales/<lang>.toml` から読み、`%LOCALAPPDATA%\repl-plugin-player\locales\<lang>.toml` にあるキーだけを上に重ねる。
- 起動のたびに、埋め込みの全文を `locales\<lang>.default.toml` へ一時ファイル→置き換えで書き直す。読込には使わず、user が全キーを見て `<lang>.toml` へ写すための参照用。
- `<lang>.toml` が無ければ空で作り、上書きはしない。
- user の `<lang>.toml` のうち、今の exe に無いキーと、placeholder（`{$…}`）が埋め込みと合わないキーは黙って捨て、埋め込みの文言を使う。toml として壊れているときはエラーで止める。
- repo の中の exe は、今までどおり repo の `locales/` を厳密に（キーと placeholder の一致を）検査して読む。

## 理由

- 全文の複写を残すと、開発者が文言を直しても user が触っていないキーまで古いまま残り、キーを消した版では起動もしなくなった（user の報告。古い複写に残った未知キーで `--help` も exit 1 になる）。
- user が変えたキーだけを持てば、版の更新で変わるのは user が触っていないキーだけになり、どのキーが user の物かを判定する仕組みが要らない。
- 版の更新でキーを消したり `{$…}` を変えたりするのは開発者の都合なので、user のファイルのその行で起動を止めない。壊れた toml は版の更新では起きず、user が手で壊したときだけ起きるので止める。
- `.default.toml` に読み取り専用属性を付けないのは、起動のたびに書き直すので編集しても消えるだけで、属性を付けると書き直す前に外す処理が要るため。

## 却下した案

- **全文の複写を初回だけ書き、上書きしない。** 開発者の修正が届かず、キーを消すと起動しなくなる。
- **base を控えて変更を判定する（dpkg の conffile・ucf の 3-way merge 型）。** user の判断で simple なほうを選んだ。重ね合わせとキーごとの結果は同じで、base の管理が要る。
- **埋め込みだけを使い、user の手直しを持たない。** 文言を変えられる用途を失う。

## 結果

- user が変えたいキーは、`<lang>.default.toml` から `<lang>.toml` へその行だけ写す。
- 版の更新で消えたキーや placeholder の変わったキーの手直しは、通知なく埋め込みの文言に戻る。
