# ADR 0035: WAV のピッチ表示に UAPMD の MPM を使う

- 状態: 採用
- 決定者: user（UAPMD の検出器の再利用と構成の単純さを優先）
- 関連: [0034](0034-recordings-as-external-wav-clips.md)（外部 WAV としての録音）

## 背景と決定

録音した単音の高さの変化を、タイムラインの波形と同時に読めるようにする。UAPMD の MPM は短い区間の基本周波数を推定できる。UAPMD の採譜コマンドでは推定値を音符単位に集約して MIDI クリップを追加するため、ビブラートなどの細かい動きを表示する用途には区間ごとの推定値が必要になる。

既存のホスト DLL から MPM を呼び、WAV を波形用に読む際に単音ピッチも求める。表示上の解析結果なのでメモリに保持し、元の WAV から再計算する。Rust 側に別の検出器を置く案もあったが、UAPMD と推定結果が異なる場合に二つの検出器を扱う必要がある。UAPMD の実装を共有すれば、ビルド時に内部ソースへの接続が必要になる一方、配布する DLL は既存の構成で済む。

表示では採譜の既定値より長い 4096 サンプルの窓を使う。48 kHz の正弦波（MIDI 41〜56、各 3 位相）では、2048 サンプルで約 108 セントだった絶対誤差の 95 パーセンタイルが約 28 セントになった。窓が長い分、発音や消音の境界はなだらかに表示される。

当初は停止後に WAV をまとめて解析していた。録音中から表示するというユーザーの要件を受け、書き出し済みの区間を別スレッドで順次解析し、停止後もその結果を引き継ぐ方式を採用した。録音用の音声を解析用キューにも渡す方式では、解析が遅れたときのバッファ容量や欠落の扱いが増える。WAV を使えば解析の遅れは表示にとどまり、書き出し済みの区間から追いつける。波形は音声の書き出し後に表示でき、ピッチは推定窓に必要なサンプルが揃ってから表示される。
