# Dedicated evolve graphs in the existing worker batch

The A/B adapter originally rendered its two unpublished graphs in serial after callbacks. Fixed-state measurement showed a 34.6 ms callback with two 17 ms graphs, exceeding the 21.33 ms device block. This repair routes those graphs through the engine's existing parallel jobs. Rust still owns event timing, gain envelopes and silent-slot ownership; C++ supplies the UAPMD graph connection.

The repair applies only while the evolve adapter is registered. Without registration the selected graph and 80% worker deadline are unchanged. During evolve, jobs use the actual block deadline: after callbacks only apply Rust gains, so the ordinary early cutoff can discard otherwise usable audio. This does not guarantee that arbitrary plugins finish within the device period.

The graph override alone removed serial summation but still observed six worker-discard blocks in a 30-second, six-worker fixed-state run at 48 kHz / 1024 frames. Do not treat this repair as establishing uninterrupted playback. A master-output snapshot can retain its last successful samples when a worker batch is discarded; nonzero snapshot peaks alone do not prove that the device received every block. Use worker-fault evidence as well as output observations.

The application therefore also keeps one core active in its Rust DLL while evolve callbacks arrive, following the reference player's measured scheduling behavior. Callback heartbeat expiry (100 ms) stops that activity on pause/device-off, and closing the mode joins the thread. This costs about one CPU core while playing; no global OS power or priority-class setting is changed. Rust additionally saves and raises ordinary-priority rendering threads to TIME_CRITICAL while evolve heartbeats arrive. Already elevated threads are left unchanged: UAPMD MMCSS workers can report relative priority 17 / base priority 25, which is stronger than TIME_CRITICAL in a normal-priority process and cannot be restored by feeding 17 to SetThreadPriority. Each thread restores its exact previous priority on its next inactive poll, before normal rendering. Worker exits release their TLS guards; a stopped device thread restores when its callback next runs. The coordinator poll is before all early returns, including stopped-transport/engine-disabled paths. Validate activity expiry, real boosts, pause restoration and normal-mode restoration with scripts/evolution-activity-test.py. For acceptance run scripts/evolution-fixed-test.py with --workers 6 --topologies evolve --seconds 90 --require-clean; this explicitly fails on worker discard, real callback deadline misses, or missing device-period processing. Delivered-block counts and elapsed time must come from the same final observation, including any synchronous load after the previous poll.

The integrated activity/eligible-priority runtime passed a 180-second fixed four-plugin run at 48 kHz / 1024 frames with zero callback deadline misses or worker discards. This is evidence for those inputs, not a guarantee for arbitrary presets or system load. Human listening remains separate.
